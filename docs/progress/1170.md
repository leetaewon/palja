## 엔진·공유 파일 요청

> 이 세션은 `src/engine/`, `sim/`, 기존 테스트, 기존 콘텐츠 줄을 고치지 않는 규칙으로 일했다. 아래는 병합 뒤 한 세션에서 정리하면 좋은 것들이다.

1. ~~**`tests/birth.test.ts`가 시점 하나만 있다고 가정한다.**~~ → main에서 해결됨(1592 시점으로 고정). 아래는 당시 기록. 출생 연도 1565~1580, 왕족 경기도·이씨, 1592 신분 분포를 모든 출생에 검사해서 시점을 하나라도 추가하면 반드시 깨진다. 고치지 않으면 `npm run test`가 통과할 수 없어, 1592 전용 검사 4개만 `births1592`(1592 출생)로 거르도록 고쳤다. 왕족 1% 검사와 성비 검사는 모든 시점 그대로다. 다른 시점 세션도 같은 줄을 고쳤을 수 있으니 병합 때 한쪽으로 맞추면 된다.
2. **기존 기록 규칙에 시점 조건이 없다.** `records.json`의 `rule-jokbo-royal`, `rule-sillok-royal-death`, `rule-jokbo-yangban-*`, `rule-jokbo-jungin`, `rule-munjip-scholar`, `rule-hojeok*`가 모든 시점에 걸린다. 1170에서는 문장이 대체로 무난하지만 "선원록"(조선 왕실 족보)은 맞지 않아 우회했다(위 결정). 제안: 기존 규칙에 `"eras": ["1592"]`를 붙이거나, 엔진 `judgeRecord`가 템플릿 `eras`에 맞지 않는 후보를 거르기.
3. **`sim/sim-lives.ts`가 신분 id `yangban`·순서 목록 `['royal','yangban','jungin','commoner','slave']`에 묶여 있다.** 새 신분(`soldier`, `bugok`)은 표 위쪽에 먼저 나온다(기능 문제는 없음). 제안: 시점 파일에 "상층 신분" 목록을 두거나 `influenceBase >= 2`로 판단, 표 순서는 시점 파일의 신분 순서를 따르기.
4. **현대 지식 문장이 시점을 가리지 않는다.** `teach-hangul`(한글), `war-prep`(왜군), 그 실록 템플릿(`sillok-hangul`, `sillok-war-prophecy`)은 1592 전용이다. 제안: 지식 항목에 시점별 문장 덮어쓰기(`byEra`)를 두거나 시점별 지식 항목("셈과 글자 가르치기", "북방 침입 대비")을 따로 추가.
5. **`mindsets.json`의 `byStatus`에 새 신분이 없다.** 부곡민·군인의 "공부" 학식 배수가 1.0이라 양민(0.5)보다 빨리 오른다. 제안: `bugok: { learning: 0.4 }`, 필요하면 `soldier`.
6. (문서) 사건 효과 순서 규칙 — 사망 효과 뒤 효과는 죽으면 적용되지 않으므로, "죽어도 남는 기록"은 사망 효과 앞에 둔다. `content-schema.md` 3장에 한 줄 적어 두면 좋다.
