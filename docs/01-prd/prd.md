## 1. 한 줄 소개

삼국시대부터 조선까지, 이 땅 어딘가에 무작위로 태어나 한 번의 일생을 산다. 죽으면 **팔자를 고치러** 같은 삶으로 회귀하거나, 전혀 다른 삶으로 환생한다.

## 2. 목표와 범위

### 2-1. 목표
- 브라우저에서 바로 하는 텍스트 중심 인생 시뮬레이션을 만든다.
- 첫 인생은 "태생이 운명을 정한다"를 체험하고, 회귀한 인생은 "그래도 바꿔 보려는 시도"를 체험하게 한다.
- 역사 근거와 게임 각색을 구분해 밝히는 **정직한 게임**을 만든다.
- 크레딧 기간(2026-11-05까지) 안에 **플레이 가능한 버전을 공개**한다.

### 2-2. 범위 밖
- 서버, 로그인, 결제, 게임 안 AI API 호출
- 외부 이미지·사운드 에셋 다운로드 (CSS·SVG·텍스트·이모지로 표현, 웹폰트는 Google Fonts 링크만)
- 대체 역사(한 인생의 변화가 다른 시점 판에 이어지는 것) — 공개 후 확장 후보
- 「80억분의 1」의 화면 구성·문구·디자인 모방

## 3. 핵심 흐름

```
타이틀 → [환생] 출생 공개 → [일생] 연 단위 진행 → [죽음] → [기록] 엔딩
       → 팔자 고치기(회귀, 같은 인생) 또는 새 환생
```

- 한 인생 5~10분. 빨리 감기와 일시정지가 있다.
- 첫 인생에서는 현대 지식을 쓸 수 없다. **회귀한 인생부터** 사건 기억과 현대 지식이 열린다.

## 4. 출생

### 4-1. 결정 순서 (모두 시드 RNG)
1. **시점**: 4개 중 균등 무작위 (`docs/04-decisions.md`)
2. **출생 연도**: 시점별 출생 구간에서 균등 무작위

| 시점 | 출생 구간 | 근거 문서 |
|---|---|---|
| 660 백제 멸망 | 630~650 | `eras/0660-baekje-fall.md` |
| 1170 무신정변 | 1145~1165 | `eras/1170-military-coup.md` |
| 1592 임진왜란 | 1565~1580 | `eras/1592-imjin-war.md` |
| 1800년대 세도정치 | 1790~1815 | `eras/1800s-sedo-politics.md` |

3. **지역**: 시점별 지역 목록과 가중치 (예: 1592는 경상·전라·충청·경기·평안 등). 지역은 사건 조건에 쓰인다.
4. **신분**: `docs/02-research/status-ratios.md`의 게임 제안값. **왕족은 모든 시점 1%**, 나머지 신분은 비례로 줄인다.
5. **성별**: 50:50
6. **가족**: 부모 신분(대체로 같음), 형제 수, 집안 재산 등급

### 4-2. 출생 공개 화면
- "○○○년, ○○ 땅의 ○○ 집안에 ○○(으)로 태어났습니다."
- 이 신분으로 태어날 확률을 보여 준다. (예: "이 시대 사람 100명 중 35명이 천민이었습니다")
- **왕족일 때 필수 안내**: "실제로는 약 1만 명 중 1명보다 드물었습니다. 이 게임은 재미를 위해 100명 중 1명으로 보정했습니다."
- "근거 보기" 버튼

### 4-3. 이름
- 시대 분위기에 맞는 가상 이름 풀에서 고른다. 노비·천민 이름도 비하적으로 짓지 않는다.
- 실존 인물과 같은 이름은 피한다.

## 5. 일생 진행

### 5-1. 능력치
| 능력치 | 범위 | 의미 |
|---|---|---|
| 건강 | 0~100 | 사망 위험에 영향 |
| 재산 | 0~100 | 기근 대처, 납속·속량·족보 매입 같은 선택지 조건 |
| 학식 | 0~100 | 과거, 기록이 남을 가능성 |
| 신뢰 | 0~100 | 주변이 내 말을 듣는 정도. 현대 지식의 효과에 쓰인다 |

### 5-2. 한 해의 흐름
1. 플레이어가 **올해의 마음가짐**을 고른다 (기본은 지난해 유지): 일 / 공부 / 가족 / 몸 돌보기 / 숨죽이기
2. 마음가짐과 신분에 따라 능력치가 조금 변한다.
3. 조건에 맞는 **사건**이 0~2개 일어난다. 연표 사건(정해진 해에 반드시 일어남)과 확률 사건(조건이 맞으면 확률로)이 있다.
4. **갈림길** 사건은 진행을 멈추고 선택을 받는다.
5. 사망 판정 (6장)

- 기본 속도: 한 해 약 3초, 빨리 감기 3배. 갈림길에서는 항상 멈춘다.
- 어릴 때(0~9세)는 마음가짐 선택 없이 자동으로 흐른다.

### 5-3. 신분 변동
- 실제로 있었던 길만 연다: 속량·납속 면천(노비→양인), 공명첩·족보 매입·유학 칭호(상민→호적상 양반, 1800년대), 전공, 몰락, 연좌로 노비가 됨 등
- 각 길은 `docs/02-research/eras/`의 갈림길 소재에서 가져온다.

## 6. 죽음

### 6-1. 사망 모델
- 매년 사망 위험 = 나이 구간 기본 위험 × 신분 보정 × 시점 보정 × 건강 보정 + 사건 사망(전쟁·역병·형벌·출산 등)
- 구간과 방향은 `docs/02-research/life-death.md` 3장을 따른다.
- **보정 목표** (시뮬레이션으로 확인)
  - 전체 평균 사망 나이: 20대 중반 (±3세)
  - 5세 이전 사망: 전체 출생의 30~40%
  - 성인(15세 이상)까지 산 사람의 평균 사망 나이: 45~55세
  - 왕족·양반은 평균보다 오래 살지만 장수가 보장되지는 않는다
- **자살은 사망 원인에서 뺀다.**

### 6-2. 어린 나이의 죽음
- 0~4세에 죽으면 짧고 담담한 엔딩으로 바로 간다. 회귀하면 같은 출생으로 돌아가 다시 시작한다. (회귀 기억으로 바꿀 수 있는 건 부모에게 미치는 작은 영향 정도)

## 7. 팔자 고치기 (회귀)

### 7-1. 규칙
- 죽은 뒤 **팔자 고치기**를 고르면 같은 인생의 출생 순간으로 돌아간다. 시점·연도·지역·신분·성별·가족이 같다.
- **한 인생당 3회**까지. 3회를 다 쓰면 새 환생만 고를 수 있다.
- 같은 시드에서 시작하지만, 플레이어 선택이 바뀌면 이후 사건 결과는 달라질 수 있다.

### 7-2. 회귀가 가져오는 것
1. **사건 기억**: 이전 회차에서 겪은 사건 중 `memorable` 표시된 사건을 기억한다. (예: "1592년 4월 부산 상륙") 기억이 있으면 해당 사건 전에 **대비 선택지**가 열린다.
2. **현대 지식**: 회귀한 인생에서는 플레이어의 현대 지식을 쓸 수 있다. 당시 없던 지식도 허용한다. (`docs/04-decisions.md`)

### 7-3. 현대 지식 행동 (예시, 최소 8개)
| 지식 | 예 |
|---|---|
| 위생 | 물을 끓여 마시기, 손 씻기, 환자 격리 |
| 종두 | 우두법으로 두창 예방 |
| 출산 | 깨끗한 천과 끓인 물로 출산 돕기 |
| 영양·저장 | 구황작물, 곡식 저장 |
| 글 | 한글·셈을 가르치기 |
| 전쟁 대비 | 피난 경로·시기, 곡식 숨기기 |
| 농법 | 거름, 물 관리 |
| 상업 | 장부, 시세 차익 |

### 7-4. 영향력 단계 — "지식이 있어도 신분이 들어주지 않는다"
현대 지식을 쓰면 **영향력**에 따라 미치는 범위가 정해진다.

| 영향력 | 조건 (대략) | 범위 | 결과 예 |
|---|---|---|---|
| 1 가족 | 누구나 | 나와 가족 | 우리 가족은 괴질을 피했다 |
| 2 마을 | 신뢰 높음 또는 재산 높음 | 마을 | 마을 사람들이 물을 끓이기 시작했다 |
| 3 고을 | 양반·향리·관료 + 신뢰 | 고을 | 고을 수령이 우물을 관리하게 했다 |
| 4 나라 | 왕족·고위 관료 + 학식·신뢰 | 나라 | **가상 실록 한 줄**이 남는다 |

- 영향력 계산식은 신분 기본값 + 재산·신뢰·학식 보정으로 엔진에서 정의한다.
- 낮은 신분이 높은 범위를 시도하면 실패하거나 의심받는다. 그 결과도 담담하게 보여 준다. (예: "사람들은 노비의 말을 귀담아듣지 않았다.")
- **세상을 바꾼 결과는 그 인생 안에서만 유지된다.** 다른 시점 판에는 이어지지 않는다.

## 8. 엔딩: 기록

1. **사인과 향년**: "○○○년 ○월, ○○(으)로 세상을 떠났습니다. 향년 ○○세."
2. **남은 기록**: 다음 중 가장 높은 것 하나 (조건은 신분·학식·행적)
   - 기록 없음: "당신의 삶은 어디에도 기록되지 않았습니다." (대부분)
   - 호적 한 줄 / 족보 한 줄 / 문집·읍지 한 줄 / **가상 실록 기사**
   - 기록 문장은 고풍 문체 (`docs/03-design/writing-guide.md`)
3. **이번 생에서 바꾼 것**: 회귀한 인생이면 바꾼 일 목록 (가족·마을·고을·나라)
4. **묘비 한 줄**: 플레이어가 직접 입력 (선택, 40자 이내, 저장만 하고 외부 전송 없음)
5. **같은 해 같은 고을의 사람들**: 같은 시점·지역에 태어난 가상 인물 3명의 한 줄 요약 (엔진으로 빠르게 시뮬레이션)
6. 버튼: 팔자 고치기(남은 횟수 표시) / 새 환생 / 결과 복사

## 9. 그 밖의 기능

| 기능 | 내용 |
|---|---|
| 인생 도감 | 시점 × 신분 조합 칸. 살아 본 조합이 채워진다 |
| 근거 보기 | 출생 확률, 주요 사건마다 근거 요약과 신뢰도([확인]/[추정]/[각색]) |
| 저장 | `localStorage`에 진행 중 인생·도감 저장. 모든 접근 `try/catch`. 저장이 안 돼도 게임은 동작 |
| 시드 | 화면에 시드 표시, 시드로 시작 가능 |
| 결과 복사 | 텍스트로 한 인생 요약 복사 |
| 안내 | 첫 화면에 "역사 연구를 바탕으로 한 추정과 게임 각색이 섞여 있습니다", 권장 15세 이상, 무거운 소재 안내 |

## 10. 화면

1. **타이틀**: 새 환생 / 이어하기 / 인생 도감 / 이 게임에 대하여(근거·영감 출처)
2. **출생 공개**
3. **일생**: 상단 연도·나이·시점, 능력치, 연대기 로그(한 해씩 쌓이는 문장), 마음가짐 선택, 속도 조절
4. **갈림길 모달**: 상황 설명 + 선택지 (회귀 기억·현대 지식 선택지는 구분 표시)
5. **엔딩: 기록**
6. **인생 도감**, **근거 보기**

### 10-1. 디자인 원칙
- 한지·먹·도장 느낌의 차분한 톤. 흔한 템플릿 느낌을 피한다.
- 가독성 우선: 본문 16px 이상, 줄 간격 넉넉하게, 명도 대비 WCAG AA (라이트·다크 모두)
- **모바일 우선.** 링크는 대부분 휴대폰에서 열린다. 360px 폭부터 깨지지 않아야 한다.
- **라이트 모드가 기본.** 첫 방문은 OS 설정과 상관없이 라이트로 시작하고, 화면의 전환 버튼으로 다크 모드를 고를 수 있다. 고른 모드는 `localStorage`에 기억한다(`try/catch`).
- `prefers-reduced-motion` 존중
- 큰 화면에서는 키보드만으로 플레이 가능

### 10-2. 화면 크기별 레이아웃
기능은 같고 **레이아웃만** 다르다. 화면 크기별로 다른 기능·제스처는 만들지 않는다.

| | 모바일 (~767px) | 큰 화면 (768px~) |
|---|---|---|
| 구성 | 한 단. 연대기가 중심 | 두 단. 왼쪽 연대기, 오른쪽 능력치·가족·기억 패널 |
| 능력치 | 상단 요약 한 줄, 눌러서 펼침 | 패널에 항상 표시 |
| 선택 버튼 | 화면 하단 고정 (엄지 영역), 터치 영역 44px 이상 | 연대기 아래, 숫자키 단축키 |
| 갈림길 | 하단에서 올라오는 시트 | 가운데 모달 |
| 속도 조절 | 하단 바 | 상단 바 |

## 11. 기술 요구사항

| 항목 | 기준 |
|---|---|
| 언어 | TypeScript (strict) |
| 빌드 / UI | Vite / React |
| 테스트 | Vitest (엔진·콘텐츠 검증), Playwright (E2E·스크린샷) |
| 배포 | **Cloudflare Pages** Git 연동 (사람이 대시보드에서 연결). 빌드 명령 `npm run build`, 출력 `dist`, Vite `base: '/'`. Node 버전은 `.node-version` 파일로 고정. main은 프로덕션, 다른 브랜치·PR은 미리보기 배포 |
| 구조 | `src/engine/` 순수 로직 (React·DOM·`window`·`localStorage` import 금지), `src/ui/`, `content/` 게임 데이터(JSON), `sim/` 시뮬레이터 |
| 난수 | 시드 RNG만. `Math.random()` 금지 |
| 결정론 | 같은 시드 + 같은 선택 → 같은 인생. 테스트로 보장 |
| 콘텐츠 검증 | `content/`의 모든 파일을 스키마로 검증하는 테스트 (`docs/03-design/content-schema.md`) |
